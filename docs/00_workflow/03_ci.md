# 03. CI trên nhánh experiment

> Đọc file này khi: CI báo đỏ, hoặc muốn biết CI kiểm những gì.
> Liên quan: `docs/06_plan/P6_reports_ci.md`, `docs/00_workflow/05_git_commits.md`

## Khi nào chạy

- Khi push lên nhánh `experiment`.
- Khi mở pull request vào nhánh `experiment`.

## Kiểm tra 8 chỗ

| #   | Kiểm gì                                                                                     | Chặn lỗi gì                           |
| --- | ------------------------------------------------------------------------------------------- | ------------------------------------- |
| 1   | Không có file **dữ liệu** bị git theo dõi, ngoài bảng chi tiết trong `pipeline/`, `eda/`   | vô tình commit dữ liệu                |
| 2   | `.gitignore` đúng: file dữ liệu bị bỏ qua, file metadata và report thì không                | mất metadata hoặc commit nhầm dữ liệu |
| 3   | Notebook đã được làm sạch output                                                            | diff GitHub đầy rác                   |
| 4   | Mọi registry đều hợp lệ (gọi `check()` cho từng trục)                                       | thêm module nhưng quên đăng ký        |
| 5   | Mọi `experiments/**/config.yaml` hợp lệ: hợp nhất được, có `roles`, dataset version tồn tại | lỗi config phát hiện muộn trên Colab  |
| 6   | `REPO_SHA` trong notebook là sha hợp lệ và tồn tại trong repo                               | ghim sai hoặc sha không tồn tại       |
| 7   | Link trong tài liệu (`README.md`, `docs/**/*.md`) trỏ tới file có thật                     | tài liệu trỏ vào file đã đổi tên      |
| 8   | Bảng số đo **mồ côi**: bảng của một bộ ví dụ/khối hệ thống đã bị sửa tại chỗ               | bảng không tái lập được vẫn nằm trong `model_input.csv` |

Kiểm 3 chặn ở CI; muốn nó khỏi phải sửa hai lần thì cài `nbstripout` trên máy mình (git sẽ tự bỏ
output khi commit, `.gitattributes` đã khai bộ lọc sẵn):

```bash
pip install nbstripout
nbstripout --install
```

Máy nào chưa cài thì bộ lọc không có tác dụng, và **không hỏng gì**: kiểm 3 vẫn là chốt cuối.

Check 1 không được phép cấm mọi file trong `data/`: theo luật 20, metadata và report **phải**
được git theo dõi. Danh sách được phép có trong `data/`:

| Nhóm                                             | Vì sao được theo dõi                        |
| ------------------------------------------------ | ------------------------------------------- |
| `raw_meta.yaml`                                  | nguồn, số dòng, sha256 của một phiên bản raw |
| `processing_log.json`, `label_map.json`           | dấu vết tạo ra dataset                      |
| `eval_lock.json`                                 | khoá tập đánh giá (vân tay tập bản ghi + byte), có từ bản dữ liệu đầu tiên |
| `pipeline/**`, `eda/**`                           | báo cáo và bảng chi tiết của từng lần chạy   |
| `data/reports/**`                                 | bảng tổng hợp năm nhóm (xem P6 T1) - thứ người đọc mở ra xem, còn mục lục `experiment_registry/runs/` thì bị bỏ qua |
| `data/reports/_archive/README.md`                 | kho lịch sử bảng số đo: giải thích vì sao bảng cũ nằm NGOÀI `model_input/` (nội dung của kho không vào git) |
| `data/assets/`, `data/reference_publication/`     | tài nguyên dùng chung và số liệu công bố     |
| `.gitkeep`                                        | giữ thư mục rỗng trong git                  |

Sau đó chạy `python -m unittest discover -s tests`.

Cấu hình chạy thật nằm ở `.github/workflows/ci.yml`: checkout với `fetch-depth: 0` (kiểm tra 6 cần
các commit cũ), cài `requirements-ci.txt` (rất ngắn, vì CI không chạy model), rồi chạy hai lệnh trên.

## CI không làm gì

- Không chạy model, không cần GPU.
- Không đọc `data/`, vì dữ liệu không nằm trong repo. Lỗi phụ thuộc dữ liệu do preflight trong notebook bắt.
  Hệ quả: nhóm test cần dataset đã xử lý tự bỏ qua trên CI (`HAS_DATASET` trong
  `tests/workflow/test_preflight.py`), nhưng vẫn chạy đủ ở máy cá nhân - nơi có dữ liệu.
- Không gọi Drive, không gọi DagsHub.
- Không chạy notebook thật.

## Khi CI đỏ

1. Mở log của bước bị đỏ, đọc dòng lỗi cuối cùng.
2. Sửa đúng chỗ, chạy lại `python scripts/ci_checks.py` và `python -m unittest discover -s tests` ở máy.
3. Commit bổ sung, không amend commit cũ.

### Máy Windows: một test đỏ vì codepage, không phải vì code

`python -m unittest discover -s tests` trên Windows có thể báo **1 lỗi** ở
`tests/workflow/test_clean.py::ModeTest::test_chay_thanh_tien_trinh_hai_lan_thi_lan_hai_rong`, kèm
`TypeError: argument of type 'NoneType' is not iterable`. Đây **không** phải lỗi sản phẩm.

Nguyên nhân là codepage, không phải logic: test chạy `scripts/clean.py` bằng
`subprocess.run(..., capture_output=True, text=True)` nên tiến trình CHA giải mã output của tiến trình
con bằng codepage hệ thống (cp1252 trên máy này), trong khi tool tự in UTF-8; thread đọc của
`subprocess` chết (`UnicodeDecodeError: 'charmap' codec can't decode byte 0x8d`) nên `stdout` thành
`None`, và assertion mới lỗi ở `first.stdout`. Cùng họ với mục "Sửa tệp văn bản có chữ tiếng Việt
(Windows)" của `06_conventions.md`, chỉ khác chiều: ở đây bên CHA giải mã, không phải bên ghi file.

Test nay khai thẳng `encoding="utf-8"` (đúng cách `src/workflow/checks.py` đọc output của `git`), nên
lỗi này không tái diễn ở chỗ đó. Nếu gặp cùng loại ở chỗ khác thì chạy bộ test bằng:

```bash
$env:PYTHONUTF8=1        # PowerShell; hoặc export PYTHONUTF8=1 trên shell khác
python -m unittest discover -s tests
```

CI là ubuntu với locale UTF-8 nên vẫn chạy lệnh trần như cũ.
